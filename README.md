# 🌸 PRR9: Экран авторизации (Clean Architecture + MVI)

Практическая работа №9 по курсу «МДК 01.03: Современные паттерны проектирования в Android».
Проект демонстрирует реализацию функционала входа в систему с использованием передовых методик Android-разработки и уникальным дизайном в нежных розовых оттенках.

##  Основные характеристики и соответствие требованиям

- ✅ **Unidirectional Data Flow (UDF):** Состояние интерфейса хранится в виде неизменяемого объекта. Любое взаимодействие пользователя (Intent) вызывает пересоздание состояния через ViewModel.
- ✅ **Реактивный подход:** Использование `StateFlow` совместно с `viewModelScope` обеспечивает мгновенную реакцию UI на изменения (проверка полей, деактивация кнопки при загрузке) без необходимости вручную обновлять интерфейс.
- ✅ **Чистая архитектура:** Явное разделение на уровни Presentation, Domain и Data. Бизнес-правила (UseCase) полностью независимы от фреймворка Android.
- ✅ **Dependency Injection:** Реализовано с помощью Hilt с генерацией кода через KSP.
- ✅ **Управление ошибками:** Ошибки отображаются посредством `SnackbarHost` (Material 3) через обновление состояния, вместо применения устаревших Toast.
- ✅ **Тестируемость:** Domain-уровень полностью изолирован и готов к написанию Unit-тестов (JUnit + MockK) без необходимости запускать эмулятор.

## 🛠 Технологический стек

- **Язык разработки:** Kotlin 2.0.21
- **UI-фреймворк:** Jetpack Compose + Material 3 (индивидуальная пастельно-розовая цветовая схема, расширенная карточка)
- **Архитектура:** Clean Architecture + MVVM/MVI
- **Асинхронность:** Kotlin Coroutines + Flow (StateFlow)
- **DI:** Dagger Hilt + KSP
- **Сборка:** Gradle (Kotlin DSL), JVM Target 17

## 📂 Структура проекта

```text
app/src/main/java/com/example/prr9/
├── di/                 # Hilt-модули (AppModule)
├── domain/             # Бизнес-логика (без Android-зависимостей)
│   ├── model/          # Доменные модели (User)
│   ├── repository/     # Контракты (интерфейсы)
│   └── usecase/        # Сценарии использования (AuthUseCase)
├── data/               # Источники данных
│   └── repository/     # Реализации контрактов (AuthRepositoryImpl)
└── presentation/       # UI-уровень (MVI)
    ├── AuthUiState.kt  # Immutable состояние экрана
    ├── AuthViewModel.kt# Обработка бизнес-логики и пользовательских действий
    ├── LoginScreen.kt  # Экран входа (Compose, расширенная карточка)
    └── HomeScreen.kt   # Экран профиля после успешной авторизации
```
